The Course Constraint Scheduler uses a **JSON** configuration that defines the scheduling problem. Everything is validated with **Pydantic** (`strict=True`, `extra="forbid"`), so typos and unknown keys fail fast with clear errors.

## Top-level structure

<Schema type="CombinedConfig" description={true} />

`config` contains rooms, labs, courses, and faculty. `time_slot_config` defines the time grid and credit-hour
class patterns; see the dedicated configuration pages for behavior and examples.

## Validation behavior

- **Cross-references** — Course rooms/labs/faculty/conflicts must name entities that exist in `config`.
- **Business rules** — e.g. faculty min/max credits, mandatory days, no self-conflicts.
- **Required capacities** — Resource capacities and each section's expected enrollment are positive integers.
- **Stable identifiers** — Course, section, faculty, resource, and feature names reject blank values and
  leading/trailing whitespace.
- **Strict types** — Times and ranges use fixed string patterns (see below).
- **No unknown keys** — Every model uses `extra="forbid"`; misspelled or future fields fail validation.
- **No coercion** — `strict=True` rejects values such as a numeric string where an integer is required.

## Type aliases (conceptual)

Times use `HH:MM` (24-hour) and ranges use `HH:MM-HH:MM`; preferences are integers from `0` to `10`; weekdays are
`MON` through `FRI`. The rendered schemas on the linked pages show the complete field types and constraints.

## JSON Schema

A generated **JSON Schema** for the full document (`CombinedConfig`) is committed at:

`fern/docs/assets/combined-config.schema.json`

You can also fetch it from GitHub:
[combined-config.schema.json (main)](https://github.com/mucsci/scheduler/raw/main/fern/docs/assets/combined-config.schema.json)

If you changed config models and need to refresh the schema locally:

```bash
uv run python scripts/export_config_schema.py
```

The **REST API** `POST /submit` body matches this shape (same model as `CombinedConfig`).

## Valid complete examples

The repository keeps complete configurations executable instead of duplicating untested JSON in several guides:

- [`tests/fixtures/minimal_config.json`](https://github.com/mucsci/scheduler/blob/main/tests/fixtures/minimal_config.json)
  is the canonical minimal configuration used by unit, integration, Python, and REST tests.
- [`example.json`](https://github.com/mucsci/scheduler/blob/main/example.json) is a larger multi-course example,
  including repeated sections and preference-derived faculty candidates.

The current schema is strict: legacy global room/lab strings and course entries without `capacity` are rejected.

Both files are validated as `CombinedConfig` in the documentation parity tests.

Continue with **Rooms and labs**, **Courses**, **Faculty**, and **Time slots** for field-level detail.
