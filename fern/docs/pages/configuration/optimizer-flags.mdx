title: Optimizer flags
description: Optional optimizer_flags that steer soft objectives on top of hard constraints.
---

**`optimizer_flags`** is an optional top-level array of these flags. Omit it or use `[]` for no extra optimization beyond feasibility.

<Schema type="OptimizerFlags" />

## Example

```json
{
  "optimizer_flags": [
    "faculty_course",
    "faculty_room",
    "pack_rooms",
    "same_room"
  ]
}
```

## Flag behavior

- `faculty_course`, `faculty_room`, and `faculty_lab` use the corresponding faculty preference maps.
- `same_room` and `same_lab` prefer eligible courses taught by one faculty member to share a resource.
- `pack_rooms` and `pack_labs` prefer different courses to use the same resource at adjacent meetings. Online
  meetings and unreserved lab meetings do not count for `pack_rooms`.

## Practices

- Start with `faculty_course` and add resource flags as needed.
- More flags can **increase** solve time; tune for your instance size.
- Hard constraints (availability, conflicts, etc.) are always enforced; flags affect **preferences**, not feasibility.
- Objectives use Pareto priority and a fixed registration order; rearranging the flag strings does not change it.
- Objective audit upper bounds score each item independently and may not be jointly attainable.
